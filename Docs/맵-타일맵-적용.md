# 맵 랜덤 시스템 → 타일맵 적용

최종 갱신: 2026-08-16 · 브랜치 `feature/random-map`

랜덤 맵 생성기를 실제 플레이에 연결하고, 방을 타일맵으로 그리기까지의 작업 목록.

---

## 1. 현재 상태

### 끝난 것

| 범위 | 내용 |
|---|---|
| 맵 트리 생성 | `StageGenerator` / `StageMap` / `MapNode` — 순수 C#, 시드 결정적 |
| 데이터 SO | `StageData` / `RoomData` / `EnemyData` + `Stage_01`·`Room_*`·`Enemy_*` 에셋 |
| 적 스탯 | `EnemyStats.Setup(data, power)` — 기준값은 SO, 배율은 스폰 시점 |
| 검증 하네스 | `Tools/StageValidate` (`dotnet run`) · 에디터 `Map/스테이지 트리 검증` |
| **주행 연결** | `GameManager`가 `StageMap`을 따라 방을 교체 · 스폰이 `node.seed` 기반 |

주행 연결에서 바뀐 파일:

- `GameManager` — `EnterMirror()`가 트리를 생성하고 `map.root`부터 시작.
  `MoveNextRoom(doorIndex)`가 `currentNode.next[doorIndex]`로 이동.
  `LoadRoom()`이 `node.room.PickVariant(node.seed)`로 프리팹을 뽑는다 —
  **타일맵 방 프리팹이 꽂히는 지점이 여기다.**
- `RoomManager` — `StartRoom(GameManager, MapNode, GameObject)`로 노드를 주입받는다.
  방 프리팹은 런타임에 `Instantiate`되므로 씬의 `GameManager`를 직렬화할 수 없다.
- `SpawnManager` — 적 종류·마릿수·스폰 지점을 전부 `node.seed`로 정한다.
  `enemyPrefab` 단일 필드는 없어졌고 `StageData.enemyPool`에서 뽑는다.
- `RoomDoorTrigger` — `doorIndex`(0=왼쪽, 1=오른쪽) 추가, 부모 `RoomManager`를 통해 보고한다.

문법·타입 컴파일 확인 완료. 씬 동작은 아래 배선 후에 확인해야 한다.

### 아직 씬에 없는 것

- 방 문에 콜라이더도 `RoomDoorTrigger`도 붙어 있지 않다 (`Room.prefab`의
  `LeftDoor`/`RightDoor`는 Transform + 자식 Square뿐)
- `Stage_01.bossPrefab`이 비어 있다
- 방 바닥이 `Square` 스프라이트다 — 타일맵 없음

---

## 2. 지금 바로 — 에디터 배선

필드가 바뀌었으므로 인스펙터 재설정이 필요하다. 이 4개를 끝내면 **지금 프리팹
그대로 5~7방 주행이 돌아간다.**

- [ ] **GameManager** — `Room Prefab` 필드가 사라졌다.
      `Stage Data`에 `Stage_01` 할당. `Mirror` / `Player`는 기존 값 유지.
      `Fixed Stage Seed`는 0으로 두면 매판 랜덤, 값을 박으면 그 판이 그대로 재현된다.
- [ ] **SpawnManager** (`Room.prefab` 안) — `Enemy Prefab` 필드가 사라졌다.
      `Enemy Spawn Points`만 채워져 있으면 된다.
- [ ] **Room.prefab의 문** — `LeftDoor` / `RightDoor` 각각에
      `BoxCollider2D`(**Is Trigger 체크**) + `RoomDoorTrigger` 추가.
      `Door Index`는 **LeftDoor = 0, RightDoor = 1**.
      (`MapNode.next` 인덱스와 같아야 한다. 뒤집히면 검증 통과한 트리와 실제
      주행이 어긋나 디버깅이 어려워진다.)
- [ ] **Stage_01.asset** — `Boss Prefab` 할당.
      비워두면 마지막 방 문을 탔을 때 에러 로그가 난다.

확인 방법: 플레이 → 거울 진입 → 콘솔에
`[GameManager] 스테이지 생성 — seed … · 깊이 …` 와 방마다
`[GameManager] 입장 — d{깊이} {타입} · seed … · power …` 가 찍히면 정상.

## 3. 다음 — 타일맵 적용

방을 손으로 그린 타일맵 프리팹으로 만들고 `RoomData.prefabVariants`에 넣는 방식.
`PickVariant(seed)`가 이미 있으므로 **맵 생성 코드는 수정하지 않는다.**

- [ ] **타일 에셋 준비**
      스프라이트 시트 → Sprite Mode: Multiple, Slice, PPU 통일,
      Filter Mode: Point, Compression: None.
      `com.unity.2d.tilemap.extras`가 이미 설치돼 있으니 **Rule Tile**을 만들어두면
      외곽/모서리가 자동 처리돼 방을 여러 개 그릴 때 시간이 크게 준다.
- [ ] **방 프리팹 구조 재구성** — `Room.prefab`의 `Square` 바닥을 타일맵으로 교체
      ```
      Room (RoomManager)
      ├── Grid                   ← 프리팹 안에 둔다. 방 단위 Instantiate/Destroy가 깔끔해진다
      │   ├── Tilemap_Ground     ← TilemapCollider2D + CompositeCollider2D + Rigidbody2D(Static)
      │   └── Tilemap_Deco       ← 콜라이더 없음
      ├── PlayerSpawn
      ├── EnemySpawnPoints/SpawnPoint1~4
      ├── LeftDoor / RightDoor   ← BoxCollider2D(Trigger) + RoomDoorTrigger
      ```
      `RoomManager`는 수정 불필요.
- [ ] **RoomType별 배리언트 제작** — 타입당 2~3개
      (`Battle_01/02`, `Elite_01`, `Merchant_01` …)
      **규격을 반드시 통일한다**: 방 크기, 문 위치, PlayerSpawn 위치.
      규격이 다르면 좌/우 어느 문으로 들어와도 같은 지점에서 시작해 이동 흐름이 깨진다.
- [ ] **RoomData에 연결** — `Assets/Prefabs/Data/Room/Room_*.asset`의
      `prefabVariants`에 위 프리팹들을 등록. 여기까지 **코드 변경 0**.

### 나중에 (선택)

배리언트를 손으로 그리는 것이 한계에 부딪히면, `RoomLayout` SO에
`TileBase[]` + 크기를 담고 `SetTilesBlock`으로 씬의 공유 Tilemap에 찍는 방식으로
넘어간다. 방 폭·발판 위치를 `node.seed`로 절차 생성할 수 있지만 작업량이 훨씬 크다.

## 4. 남은 코드 작업

- [ ] **되돌아가기 시 적이 다시 스폰된다**
      `GameManager.MovePrevRoom()`은 만들었지만 `RoomManager`가 `node.cleared`를
      확인하지 않아, 클리어한 방에 다시 들어가면 적이 또 나온다.
      `StartRoom`에서 `mapNode.cleared`면 스폰을 건너뛰고 바로 문을 열어야 한다.
- [ ] **`MovePrevRoom()` 호출부가 없다** — 뒤로 가는 문/입력이 아직 없다
- [ ] **상인·보상·휴식 방** — 현재는 입장 즉시 클리어 처리(문 개방)만 한다.
      상점 UI, 보상 선택, 회복 동작이 필요하다.
- [ ] **보스방** — `RoomManager`가 보스 타입일 때 스폰도 자동 클리어도 하지 않는다.
      보스 프리팹이 보스를 직접 들고 있다고 가정한 상태. 보스 처치 → 클리어 연결 필요.
- [ ] **스테이지 클리어 → 다음 스테이지** — 보스방에서 문을 타면
      `"다음 스테이지 전환은 아직 미구현"` 로그만 찍고 끝난다.
- [ ] **난이도 곡선 검토** — `EnemyPower = 1 + depth * powerPerDepth`(기본 0.15).
      깊이 6이면 x1.9. `Tools/StageValidate` 출력의 난이도 배율 표로 확인.

---

## 5. 주의점

- **타일맵 콜라이더** — `TilemapCollider2D` 단독은 타일마다 콜라이더가 생긴다.
  타일에 `Used By Composite` + `CompositeCollider2D` + `Rigidbody2D(Static)` 조합 필수.
- **방 전환 비용** — 방마다 Grid째로 `Destroy`/`Instantiate`하면 스파이크가 난다.
  방이 커지면 이전 방 하나를 풀링하거나 `SetTilesBlock` 방식으로 넘어간다.
- **정렬** — Tilemap Renderer의 Sorting Layer / Order in Layer를 플레이어·적 기준으로
  **미리** 정한다. 배리언트를 여러 개 만든 뒤에 고치면 전부 손봐야 한다.
- **시드 결정성** — 방 안에서 `Random.Range`를 쓰면 되돌아가기가 깨진다.
  방 구성에 관여하는 난수는 전부 `new System.Random(node.seed)`에서 나와야 한다.
- **검증 하네스 위치** — `Tools/`는 `Assets/` 밖에 있어야 한다.
  안으로 옮기면 유니티가 `UnityStubs.cs`를 컴파일하려다 진짜 `UnityEngine`과 충돌한다.
