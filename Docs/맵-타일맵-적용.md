# 맵 랜덤 시스템 → 타일맵 적용

최종 갱신: 2026-08-19 · 브랜치 `feature/random-map`

랜덤 맵 생성기를 실제 플레이에 연결하고, 방을 타일맵으로 그리기까지의 작업 목록.

---

## 1. 현재 상태

### 끝난 것

| 범위 | 내용 |
|---|---|
| 맵 트리 생성 | `StageGenerator` / `StageMap` / `MapNode` — 순수 C#, 시드 결정적 |
| 데이터 SO | `StageData` / `RoomData` / `EnemyData` + `Stage_01`·`Room_*`·`Enemy_*` 에셋 |
| 적 스탯 | `EnemyStats.Setup(data, power)` — 기준값은 SO, 배율은 스폰 시점 |
| 검증 하네스 | `Tools/StageValidate` (`dotnet run`) · 에디터 `Map/스테이지 트리 검증` |
| 주행 연결 | `GameManager`가 `StageMap`을 따라 방을 교체 · 스폰이 `node.seed` 기반 |
| **develop 병합** | 보상·상점·상호작용 시스템과 통합 (`368cc63` → `ccd1ea6`) |
| **되돌아가기** | `BackDoor`로 부모 노드 복귀 · 클리어한 방 재입장 시 재스폰 없음 |

### develop 병합으로 바뀐 것 — 중요

develop이 방 흐름 코드를 다시 쓰면서 **문 조작 방식이 바뀌었다.**

- **문은 밟는 게 아니라 E키로 쓴다.** `RoomDoorTrigger`가 `InteractRule`을 구현하고,
  플레이어의 `PlayerInteract`가 트리거 안에서 E를 받아 `Interact()`를 부른다.
  → 문에 **트리거 콜라이더가 반드시 있어야 한다.** 없으면 프롬프트조차 안 뜬다.
- **`Room.prefab` → `MirrorRoom.prefab`으로 이름이 바뀌었다** (guid는 동일해서
  `RoomData.prefabVariants` 참조는 안 깨졌다). 문은 `Door.prefab` 인스턴스다.
- 방 클리어 시 별가루(`CurrencyWallet`)와 보상 패널(`RewardManager`)이 붙는다.

### 파일별 역할

- `GameManager` — `EnterMirror()`가 트리를 생성하고 `map.root`부터 시작.
  `LoadRoom()`이 `node.room.PickVariant(node.seed)`로 프리팹을 뽑는다 —
  **타일맵 방 프리팹이 꽂히는 지점이 여기다.**
  `HandleRoomExit()`이 문 종류로 분기한다 — 뒤 문이면 `MovePrevRoom()`,
  아니면 `MoveNextRoom(door.DoorIndex)`.
  develop 쪽 상점·보상 초기화(`Awake`, `EnterReality`)는 그대로 살아 있다.
- `RoomManager` — `StartRoom(GameManager, MapNode, GameObject)`로 노드를 주입받는다.
  방 프리팹은 런타임에 `Instantiate`되므로 씬의 `GameManager`를 직렬화할 수 없다.
  문은 `RoomDoorTrigger[] doors` 배열 하나로 관리한다 — 문을 늘려도 코드가 안 늘어난다.
- `SpawnManager` — 적 종류·마릿수·스폰 지점을 전부 `node.seed`로 정하고,
  처치마다 `CurrencyWallet`에 별가루를 넣는다.
- `RoomDoorTrigger` — `doorIndex`(0=왼쪽, 1=오른쪽)와 `isBackDoor`를 들고,
  `Entered` 이벤트로 부모 `RoomManager`에 보고한다.

### 방 타입별 클리어 처리

| 타입 | 동작 |
|---|---|
| `Battle` / `Elite` | 적 스폰 → 전멸 시 `RoomClear()` (별가루 + 보상 패널) |
| `Treasure` | 입장 즉시 `RoomClear()` — 보상 선택이 방의 목적이므로 |
| `Merchant` / `Rest` | 입장 즉시 `ClearWithoutReward()` — 문만 연다 (전용 UI 미구현) |
| `Boss` | 스폰도 자동 클리어도 안 함. 보스 프리팹이 보스를 직접 들고 있다고 가정 |
| 이미 클리어한 방 | `ClearWithoutReward()` — 재스폰도 보상 재지급도 없다 |

### 작업 씬 — `MapTestScene`

`TestScene`을 복사해 만들었다. `SampleScene`에는 develop의 신규 시스템
(`PlayerInteract`·`CurrencyWallet`·`ShopManager`)이 배치돼 있지 않아
**문을 쓸 수단 자체가 없다.** 빌드 세팅에는 `MainMenuScene` + `SampleScene`만
등록돼 있으니, 개발 씬을 어느 쪽으로 확정할지는 팀과 정리가 필요하다.

### 아직 없는 것

- `Stage_01.bossPrefab`이 비어 있다 (보스 프리팹 자체가 프로젝트에 없다)
- 방 바닥이 `Square` 스프라이트다 — 타일맵 없음
- `BackDoor`가 일반 문과 스프라이트가 같아 눈으로 구분이 안 된다

## 2. 지금 바로 — 에디터 배선

- [ ] **Player에 `Inventory` 컴포넌트 추가** (`MapTestScene`)
      지금 Player에는 `MemoryInventory`가 붙어 있는데 **스크립트 파일이 없다**
      (인스펙터에 `Missing (Mono Script)`). develop에서 `Inventory`로 정리되면서
      씬의 옛 컴포넌트만 남았다.
      `GameManager.Awake()`가 `player.GetComponent<Inventory>()`를 넘기는데 이게
      null이면 → `RewardManager.SelectReward()`가 항상 false →
      **보상 패널이 안 닫히고 `GameplayInputLock`이 걸린 채로 판이 잠긴다.**
      Missing 컴포넌트를 지우고 `Inventory`를 붙일 것.
- [ ] **`Stage_01.asset`의 `Boss Prefab`**
      비워두면 마지막 방 문을 탔을 때 에러 로그만 나고 멈춘다.
      보스방 프리팹부터 만들어야 한다. `MirrorRoom.prefab`을 임시로 꽂으면
      `RoomManager`가 Boss 타입에서 문을 잠근 채 두므로 소프트락이 된다.
- [ ] **`BackDoor` 위치·외형** (`MirrorRoom.prefab`)
      지금 x = -6에 임시로 놓여 있다. `BackDoor > Square`의 SpriteRenderer 색만
      바꿔도 전진 문과 구분된다.

확인 방법: 플레이 → 거울 진입 → 콘솔에
`[GameManager] 스테이지 생성 — seed … · 깊이 …` 와 방마다
`[GameManager] 입장 — d{깊이} {타입} · seed … · power …` 가 찍히면 정상.
첫 방(루트)에서는 뒤 문이 열리지 않아야 한다.

## 3. 다음 — 타일맵 적용

방을 손으로 그린 타일맵 프리팹으로 만들고 `RoomData.prefabVariants`에 넣는 방식.
`PickVariant(seed)`가 이미 있으므로 **맵 생성 코드는 수정하지 않는다.**

- [ ] **타일 에셋 준비**
      `Assets/Resources/free-exclusion-zone-tileset-pixel-art`에 스프라이트 시트를
      받아뒀다. Sprite Mode: Multiple, Slice, PPU 통일,
      Filter Mode: Point, Compression: None.
      `com.unity.2d.tilemap.extras`가 이미 설치돼 있으니 **Rule Tile**을 만들어두면
      외곽/모서리가 자동 처리돼 방을 여러 개 그릴 때 시간이 크게 준다.
- [ ] **방 프리팹 구조 재구성** — `MirrorRoom.prefab`의 `Ground`를 타일맵으로 교체
      ```
      MirrorRoom (RoomManager)
      ├── Grid                   ← 프리팹 안에 둔다. 방 단위 Instantiate/Destroy가 깔끔해진다
      │   ├── Tilemap_Ground     ← TilemapCollider2D + CompositeCollider2D + Rigidbody2D(Static)
      │   └── Tilemap_Deco       ← 콜라이더 없음
      ├── PlayerSpawn
      ├── EnemySpawnPoints/SpawnPoint1~4
      ├── Door (x -13)           ← RoomDoorTrigger: doorIndex 0
      ├── Door (x +13)           ← RoomDoorTrigger: doorIndex 1
      └── BackDoor               ← RoomDoorTrigger: isBackDoor
      ```
      문은 `Door.prefab` 인스턴스이고, 트리거 `BoxCollider2D`는 `Door.prefab` 쪽에 있다.
      `RoomManager`는 수정 불필요 — `doors` 배열에 문을 넣기만 하면 된다.
- [ ] **RoomType별 배리언트 제작** — 타입당 2~3개
      (`Battle_01/02`, `Elite_01`, `Merchant_01` …)
      **규격을 반드시 통일한다**: 방 크기, 문 위치, PlayerSpawn 위치.
      규격이 다르면 좌/우 어느 문으로 들어와도 같은 지점에서 시작해 이동 흐름이 깨진다.
- [ ] **RoomData에 연결** — `Assets/Prefabs/Data/Room/Room_*.asset`의
      `prefabVariants`에 위 프리팹들을 등록. 여기까지 **코드 변경 0**.

### 나중에 (선택)

배리언트를 손으로 그리는 것이 한계에 부딪히면, `RoomLayout` SO에
`TileBase[]` + 크기를 담고 `SetTilesBlock`으로 씬의 공유 Tilemap에 찍는 방식으로
넘어간다. 방 폭·발판 위치를 `node.seed`로 절차 생성할 수 있지만 작업량이 훨씬 크다.

## 4. 남은 코드 작업

- [ ] **상인·보상·휴식 방** — 상인과 휴식은 입장 즉시 문만 열린다.
      상점 UI, 회복 동작이 필요하다. (보물방은 보상 패널로 연결돼 있다.)
- [ ] **보스방** — `RoomManager`가 보스 타입일 때 스폰도 자동 클리어도 하지 않는다.
      보스 프리팹이 보스를 직접 들고 있다고 가정한 상태. 보스 처치 → 클리어 연결 필요.
- [ ] **스테이지 클리어 → 다음 스테이지** — 보스방에서 문을 타면
      `"다음 스테이지 전환은 아직 미구현"` 로그만 찍고 끝난다.
- [ ] **보상 실패 시 잠금 방지** — `RewardManager.GenerateRewards()`가
      `inventory == null`이어도 패널을 띄운다. 가드를 넣으면 인벤토리가 빠져 있어도
      문이 열려서 판이 통째로 잠기는 일은 막을 수 있다.
- [ ] **난이도 곡선 검토** — `EnemyPower = 1 + depth * powerPerDepth`(기본 0.15).
      깊이 6이면 x1.9. `Tools/StageValidate` 출력의 난이도 배율 표로 확인.

## 5. 주의점

- **문에는 트리거 콜라이더가 필수다** — `PlayerInteract`가 `OnTriggerEnter2D`로
  대상을 잡는다. 콜라이더가 없으면 E 프롬프트조차 안 뜬다.
  실제로 `Door.prefab`에 콜라이더가 없어서 방 이동이 통째로 막힌 적이 있다.
- **`doorIndex`는 `MapNode.next` 인덱스와 같아야 한다** — 0=왼쪽, 1=오른쪽.
  뒤집히면 검증 통과한 트리와 실제 주행이 어긋나 디버깅이 어려워진다.
  뒤 문은 `isBackDoor`로 구분하며 `doorIndex`를 쓰지 않는다.
- **타일맵 콜라이더** — `TilemapCollider2D` 단독은 타일마다 콜라이더가 생긴다.
  타일에 `Used By Composite` + `CompositeCollider2D` + `Rigidbody2D(Static)` 조합 필수.
- **방 전환 비용** — 방마다 Grid째로 `Destroy`/`Instantiate`하면 스파이크가 난다.
  방이 커지면 이전 방 하나를 풀링하거나 `SetTilesBlock` 방식으로 넘어간다.
- **정렬** — Tilemap Renderer의 Sorting Layer / Order in Layer를 플레이어·적 기준으로
  **미리** 정한다. 배리언트를 여러 개 만든 뒤에 고치면 전부 손봐야 한다.
- **시드 결정성** — 방 안에서 `Random.Range`를 쓰면 되돌아가기가 깨진다.
  방 구성에 관여하는 난수는 전부 `new System.Random(node.seed)`에서 나와야 한다.
- **검증 하네스 위치** — `Tools/`는 `Assets/` 밖에 있어야 한다.
  안으로 옮기면 유니티가 `UnityStubs.cs`를 컴파일하려다 진짜 `UnityEngine`과 충돌한다.
